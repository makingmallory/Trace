# Next-day forecasting

`forecastTargetAsOf` is the historical backtesting entry point. It creates a strict snapshot at the end of the requested local date and forecasts only the following date. `forecastTomorrow` applies the same operation to selected top-level analysis descriptors. Results are derived, deterministic, local-only objects; they are not persisted, synced, or treated as source truth.

The engine supports numeric, count, duration, time, explicitly ordered scales, booleans, nominal choices, and multi-select choices. Nominal and multi-select answers are represented as separate binary probabilities; nominal probabilities are normalized, while multi-select probabilities intentionally are not. Occurrence Trackables are deferred because an ordinary Quick Log does not itself establish a complete daily no-event denominator.

Every candidate uses only cutoff-available lagged values and known calendar facts. Same-day values, rolling external values, and event flags are deliberately excluded because ordinary tomorrow events are not known. The feature frame is generated from `snapshotForFeatureCutoff`, so facts entered after the historical cutoff cannot alter an as-of forecast. The feature engine remains the only source of generated features.

Forecast capability progresses independently of model complexity. A basic baseline needs 8 recorded days (numeric/ordered or categorical), at least 5 recordings in the most recent 30 days, and a latest recording no older than 21 days. These target-aware settings are centralized in `defaultForecastPolicy`; a handful of values or stale history still yields a specific insufficient-history reason. A baseline can be temporally validated after enough expanding holdouts exist. Only then do complete predictor rows, adequate target variation, class support, and at most 55% missingness permit a richer candidate. Constant and near-constant binary targets remain forecastable with a Beta(1,1)-smoothed prevalence over the most recent 30 observations; logistic modeling requires at least four examples of each class. No fixed 30-value gate controls basic forecast availability.

Models are small deterministic ridge regressions for numeric/ordered targets and L2-regularized logistic models for binary category labels. A short deterministic regularization grid is tuned on earlier expanding-window folds, leaving the latest fold out of hyperparameter selection. Numeric forecasts use MAE; binary labels use Brier score; nominal choices aggregate label Brier scores. A model is used only when it beats the recent-history baseline across most folds; otherwise that baseline remains the selected forecast.

Predictor selection starts with target lags and calendar features, then permits cutoff-safe lagged predictors already screened by relationship discovery. Relationship review feedback applies only a bounded ranking preference to eligible predictor features; it never overrides validation. The engine also compares a target's detected current regime with full history when the regime has enough data and uses it only when its own temporal validation is materially better.

Numeric/ordered uncertainty uses the 80th percentile of absolute holdout residuals only with at least 12 residuals, otherwise recent 10th–90th percentile dispersion, otherwise a bounded target-specific fallback. Configured scale limits, rather than the observed extremes, bound the interval. A range spanning at least 80% of a bounded domain is marked uninformative and presented as an estimate with explicit uncertainty, never as a useful “likely range.” Confidence considers capability, sample size, latest-record age, validation, and normalized range width or probability concentration. These ranges are descriptive, not medical confidence intervals.

The worker-backed Forecast panel and the compact Home Tomorrow glance share the same prediction provider and persisted target selection. Home displays at most three ready selected targets and reloads when local data changes. The Home link opens Trends → Forecast directly; no second forecasting implementation is present.

## Seven-day outlook

`forecastTargetRangeAsOf` is the deterministic historical multi-step API. It first freezes the complete data universe and all training outcomes at cutoff D, then advances h1 through h7 from that snapshot. A successful prior target forecast is added only to a derived in-memory copy as a feature input with explicit recursive provenance; it never becomes a training outcome, and the repository and raw observations are never modified. Numeric point estimates feed later target lags. Binary values use a deterministic 0.5 threshold, nominal values use the highest-probability option, and multi-select values use options at or above 0.5 (falling back to the most likely option). Those hard categorical recursion rules are deliberately documented, and later-horizon probability shrinkage reflects their added uncertainty.

Future feature availability is typed as calendar-known, historically-known, recursive-target, or unavailable-future, and the same classifier actively prunes each horizon's predictor set. Calendar features remain available throughout the week. Target lags may transition from observed to recursively predicted inputs. External lags are used only while their source date is still at or before D; future Quick Logs, events, and same-day future Trackables remain unavailable.

Horizon calibration uses exact-date historical comparisons and skips days without a target observation. Numeric/ordinal ranges use the horizon's empirical baseline errors when at least eight comparisons exist; otherwise the prior calibrated width expands by the square root of horizon. Probabilities shrink conservatively toward their uninformative center with horizon and calibration error. Capability is horizon-specific: the required evidence increases by three observed days per additional horizon, so a target may be ready tomorrow, rough for a few days, then insufficient. Direct horizon-specific models are not included in this milestone; every day uses the validated recursive one-step strategy and retains its own baseline/model diagnostics.

The Forecast worker handles both horizons. A revision-aware derived cache key includes data revision, cutoff date, sorted target selection, horizon, review revisions, and forecast configuration version. The 7-day UI is a compact per-target list with seven local dates, mixed ready/rough/insufficient states, a weekly confidence sentence, and optional explanation. Home intentionally remains Tomorrow-only.
