# Relationship discovery and target regimes

`discoverRelationships(data, request)` computes a read-only, target-scoped `RelationshipCatalog`. It selects one canonical analysis target, generates one longitudinal feature frame, aligns each predictor with observed target dates, screens each pair, evaluates survivors through expanding walk-forward folds, and groups redundant survivors. `discoverRelationshipsFromProvider` loads the existing `AnalyticsProvider` once. No relationship records or cache are persisted or synced. Results are deterministic for the same data and request.

The catalog retains every screened candidate, including reasons, support, aligned dates, fold diagnostics, mapping provenance, and suppression links. `ranked` contains only validated representatives. `filterRelationshipCandidates` applies a minimum strength tier; `formatRelationshipDiagnostics` prints a test/developer view. IDs derive from stable target descriptor, optional target option, and feature key. Source metadata and transformations are the feature engine's definitions.

## Outcomes and screens

- Continuous, count, duration, and time targets use numeric values. Ordinal targets use their configured rank order; rank gaps are **not** interpreted as equal clinical distances. Binary targets use explicit Yes/No observations. Occurrence targets use logged Yes and stored explicit No assertions; an unlogged day is not treated as No. Nominal and multi-select targets are screened as separate one-versus-rest option outcomes, never numeric category codes. A recorded multi-select answer supplies observed absence for options it did not select.
- Numeric and ordinal predictors use generated numeric/rank features; categorical and multi-select predictors use generated option indicators. Event count, post-window, and days-since predictors use the feature engine's event cells and structured predicates. Calendar terms remain optional generic controls/candidates.
- Defaults in `defaultRelationshipPolicy`: 30 aligned observations, at least 8 cases per binary class or selected category, 3 distinct event records from 3 event episodes, 18 training observations, 6 validation observations per fold, and at least 3 folds. Episode counting groups events on consecutive calendar days; many target observations after one episode do not meet event support. Missing or unmapped cells never become zero. Event predictor cells with `no-recorded-event` can be used as absence of a **logged** occurrence, while the support metadata keeps that status separate from `explicit-no`; neither is relabeled as an assertion about unlogged real-world events.
- Raw numeric/ordinal association uses Spearman rank correlation; binary predictors with binary targets use rate difference, and other binary pairs use point-biserial/Pearson. The effect magnitude is a univariate slope or rate/level difference and standardized effect is correlation. These descriptive statistics are not causal estimates or p-values.

## Validation and ranking

Folds expand training chronologically and validate in later blocks; there is no random split. The target-only baseline is a recent seven-observation mean for numeric targets and Laplace-smoothed prevalence for binary outcomes. Ordinal targets use one cumulative binary boundary per ordered category step, with prevalence baselines and an averaged Brier score across boundaries; category rank gaps have no numeric loss meaning. The candidate adds a univariate residual adjustment fitted only on its training block. Validation uses MAE for numeric and Brier score for binary/ordinal. Prior observed outcomes become available to the baseline one date at a time during validation. This is a one-step observational screen, not a future forecasting model.

A candidate needs at least 2% weighted out-of-sample improvement, a 60% fold win rate, 67% direction consistency, 20% effect-magnitude consistency, and absolute standardized effect of 0.1. Moderate and strong tiers require larger improvement/effect/support; all thresholds are centralized in `defaultRelationshipPolicy`. Failed screens retain specific machine reasons. No raw p-value ranking is used. Near-duplicate candidates with the same target, source, family, compatible option/predicate and window scale are suppressed when their generated values correlate at least 0.96 in absolute value. The strongest validated representative remains ranked; the suppressed definition remains inspectable.

## Change points and regimes

`detectTargetChangePoints` performs target-specific deterministic binary segmentation of observed target values. It requires at least 15 observations on each side, a standardized center shift of 0.8 (or binary rate change of 0.25), a robust median shift for numeric outcomes, and a score gate of 3. It returns up to three shifts with pre/post support, centers, strength heuristic, and target-specific regime boundaries. Detection uses the target history only. Nearby canonical occurrence or structured events within seven days are recorded as `nearby-in-time` context, never as a cause. Candidates retain full-history support and current-regime support after a shift; `evaluateCurrentRegime` optionally adds separate walk-forward scores when that regime has enough data. Older history remains available. Future modeling can choose a regime or weighting scheme without changing raw data.

## Limits

The screening model is univariate and does not control confounders or establish causation. Its baseline and scores are exploratory, not calibrated prediction guarantees. Nominal targets are separate binary screens, rather than one multiclass probability model. The frame's candidate cap and categorical-cardinality policy still apply, and relationship discovery does not regenerate omitted features. Change-point dates and effect heuristics are exploratory and can react to trends or changes in recording behavior. The timestamp cutoff follows the feature engine's conservative snapshot semantics; historical edits cannot be reconstructed from current snapshots. No Insights UI, forecasting, final model, or medical interpretation is included.
