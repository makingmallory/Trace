# Insights review layer

`discoverInsightCatalogs` runs the existing target-scoped relationship engine for recorded analysis descriptors in a Web Worker. Results are derived and are never saved as source data. The engine still tests and retains every technical lag/window/statistic candidate. `groupRelationshipFamilies` also runs in that worker, joining candidates sharing a target option, predictor source/predicate, broad meaning and compatible direction. Numeric lag and rolling level summaries may group; variability, slope, option presence and distinct event predicates do not silently merge. One defensible moderate/strong non-redundant representative is selected by validation improvement, stability, effect size and support. Near-tied windows receive broad temporal wording; exact candidates remain in `members` and diagnostics.

The engine's exact candidate ID remains available for modeling. User reviews now use a separate deterministic family identity based on target descriptor/option, predictor source/predicate, broad meaning and semantic direction—not window length, sample count or score. Existing local exact-ID reviews are recognized through current family members or reconstructed from their saved feature metadata, then normalized in place with the original technical ID retained. A review stores the representative evidence signature at review time; the UI notes a coarse material change in tier, direction, improvement band or support band. A change of winning window alone does not create another review question. Reviewed families are not automatically requeued in this milestone; a person can edit the retained review when changed evidence is shown. This conservative rule avoids treating a technical-window change as a new human question. This does not treat feedback as objective truth.

The primary session selects up to three diverse unreviewed families and pins those identities. Saving one reduces the visible remainder; it never backfills automatically. After the session, an optional **Review more patterns** action selects another bounded batch from eligible backlog. Diversity selection prefers new target parents and predictor sources, then relaxes to at most two per parent before falling back when only one target has credible findings. It suppresses neither source candidates nor future opportunities.

Feature `rolling.observed-count` is classified as data availability and excluded from ordinary substantive Insights, while retained in diagnostic catalogs. Event occurrence/count features remain eligible; a Quick Log count is not equated to an answered-routine count. `routineCoverage` uses configured RoutineItems and completed Check-In records, evaluates conditional rules using stored answers, and divides answered days only by known eligible days. Hidden days do not enter the denominator; days with an unavailable condition answer are marked unknown rather than presumed ineligible. The central policy requires at least 14 known eligible days and at least 80% answer coverage to label a question routinely answered. Observation-density features are conservatively suppressed even below that threshold because answer frequency alone is not a substantive health value. Historical eligibility cannot always be reconstructed when routine rules were edited without version history or when conditioning answers were not stored.

Change-point identity includes target, option, direction and estimated date. Reconnection first matches exactly, then matches the same target/direction within seven days, accommodating small segmentation jitter. Distinct same-direction shifts within that interval may need a more discriminating regime identifier in a future milestone.

Reviews are user-authored metadata in a separate local IndexedDB database (`trace-insight-reviews`). They survive reloads and can be edited or reset. They are deliberately **not synced or backed up through Google Sheets** in this milestone. Raw observations and the existing sync collection schema are unchanged. `reviewFeedbackWeight` provides a bounded, confidence-sensitive prior for future modeling; no present analysis or forecast is modified by feedback.

The browser worker is created only when Insights is first opened. It is kept mounted across Explore/Insights navigation and is refreshed when the existing Trends data loader responds to `trace:data-changed`. No generated candidate is treated as authoritative persisted data.
